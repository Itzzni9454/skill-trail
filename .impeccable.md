# Design Context — Offline Roadmaps

## What this is

A self-hosted, offline clone of roadmap.sh. One user (a developer studying a
curriculum) browses ~97 roadmaps, marks topics as learning/done/skipped, and tracks
study velocity. No accounts, no network, no collaboration.

## Audience

A single technical user, mid-study, at their own machine. They are not a "user" in the
product sense — they are the owner of the tool. They will spend long sessions in the
roadmap canvas and check the dashboard weekly. They are fluent in developer tooling and
have a low tolerance for interface condescension: no onboarding tours, no tooltips
explaining what "done" means, no marketing voice.

## Use cases, in priority order

1. **Find a roadmap and resume it.** The library is a means to an end; the canvas is the
   destination.
2. **Work through the canvas.** Click a node, read the official topic content, mark
   status, follow resource links, move on. This is the screen they live in.
3. **See whether the effort is working.** Dashboard: streak, velocity, completion
   forecast, what is due for review.
4. **Explore laterally.** Universe (cross-roadmap graph) and Mindmap (six layouts) are
   the tools for finding connections.

## Brand personality

**Precision editorial.** The register of Linear, Vercel, Stripe's dashboard: confident,
quiet, exact. It should read as instrumentation, not as a product page.

Concretely:
- Typography carries the design. Tight negative tracking on headings, generous leading on
  body, tabular figures on every number.
- Restraint over decoration. One accent colour. Hairline borders. No gradients, no glows,
  no glassmorphism.
- Density is a feature. This is a tool for reading structured information; airy
  card-grids waste the user's screen.
- Colour is reserved for state — done / learning / skipped / due. If everything is
  coloured, nothing reads as a signal.

Explicitly **not**: playful, gamified-chunky, corporate-generic, or skeuomorphic.
(The RPG skill-tree view is deliberately the one loud exception — it earns its
loudness by being opt-in.)

## Hard constraints

- **Balsamiq Sans is the fidelity contract.** The SVG roadmap canvas must keep rendering
  in Balsamiq at the exact geometry `renderer.ts` encodes. It is scoped to the canvas and
  must never leak into the chrome. `scripts/verify_edges.py` guards the geometry.
- **Fully offline.** No CDN fonts, no external requests at runtime. Typefaces are
  self-hosted in `app/public/fonts/ui/`.
- **No new runtime dependencies** unless genuinely required — the app ships with React,
  React Router, and lucide-react only.
- Must respect `prefers-reduced-motion` and keep visible focus rings.

## Differentiation — the one thing to remember

The canvas is the official renderer, pixel-exact. Everything around it is a precise
instrument. The memorable moment is the contrast: a genuinely hand-drawn roadmap sitting
inside a calm, exact, typographic shell. Lean into that rather than trying to make the
canvas look "designed".

## Typography

| Role | Family | Notes |
|---|---|---|
| UI / body | **Geist** | 400 / 500 / 600. Never Inter. |
| Numerals, labels, code | **Geist Mono** | Tabular figures for all stats. |
| Roadmap canvas only | **Balsamiq Sans** | Never used in the chrome. |

## Colour

Four themes, all derived from one semantic token layer (`--bg`, `--surface`, `--text`,
`--border`, `--accent`, state colours). Defined in `oklch`.

| Theme | Intent |
|---|---|
| `light` | Cool, crisp, default. Paper-white with a faint cool cast. |
| `paper` | Warm editorial. Ink on cream. For long reading sessions. |
| `dark` | Neutral deep grey. Not black — `#000` is banned. |
| `midnight` | Blue-black, higher contrast, for dark rooms. |

## Motion

Exponential ease-out (`cubic-bezier(0.16, 1, 0.3, 1)`) at 120–260ms. Animate state
transitions only — hover, focus, panel entry, number changes. Never animate layout
properties. No bounce, no spring overshoot, no infinite decorative loops.
